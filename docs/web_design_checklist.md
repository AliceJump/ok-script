# Web 端同构桌面端设计清单（细化版）

> 目标：参考当前桌面端设计，规划一套职责与流程相似的 Web 端方案，确保核心能力可复用、行为可对齐、上线可运维。

## 1. 同构映射清单（桌面端 -> Web 端）

- [ ] `MainWindow` -> `WebShell`（页面壳、导航、顶部状态、全局通知）
- [ ] `StartController` -> `SessionController`（启动/停止/重启、运行态切换）
- [ ] `TaskExecutor` -> `TaskRuntime`（任务排队、执行、取消、恢复）
- [ ] `DeviceManager` -> `TargetManager`（目标连接、能力探测、连接状态）
- [ ] `FeatureSet` -> `FeatureRegistry`（识别特征加载、刷新、版本一致性）
- [ ] `GlobalConfig` -> `WebConfig`（全局配置、持久化、运行时覆盖）
- [ ] `Communicate` -> `EventBus`（前后端事件总线、广播与订阅）

## 2. 分层架构清单

- [ ] 表现层：页面布局、组件库规范、主题与暗色模式策略
- [ ] 控制层：控制器边界清晰（仅编排，不承载底层业务）
- [ ] 运行层：任务生命周期管理、并发/互斥控制、异常收敛
- [ ] 能力层：截图、输入、OCR、模板识别能力抽象一致
- [ ] 基础层：日志、配置、国际化、健康检查、版本信息

## 3. 页面与导航清单

- [ ] 启动页（Start）：目标选择、连接检测、启动入口
- [ ] 任务页（Tasks）：任务列表、运行状态、队列可视化
- [ ] 设置页（Settings）：全局参数、高级选项、导入导出
- [ ] 调试页（Debug）：截图预览、识别结果、诊断信息
- [ ] 关于页（About）：版本、更新、项目链接与说明
- [ ] 导航结构与桌面端 Tab 语义保持一致

## 4. 状态机与事件流清单

- [ ] 统一状态：`idle / starting / running / stopping / error`
- [ ] 统一事件：启动、停止、任务切换、目标变更、配置更新、异常上报
- [ ] 事件幂等：重复点击启动/停止不产生脏状态
- [ ] 状态可恢复：异常后可回到 `idle` 并允许再次启动
- [ ] 关键事件具备审计日志（时间、来源、对象、结果）

## 5. 任务系统同构清单

- [ ] 支持一次性任务、触发任务、调度任务三类模式
- [ ] 任务定义模型包含：参数、前置条件、超时、重试、优先级
- [ ] 任务执行支持：暂停、取消、失败重试、终止清理
- [ ] 队列策略可配置（FIFO/优先级）
- [ ] 任务结果统一结构：成功/失败、耗时、错误码、上下文

## 6. 配置与国际化清单

- [ ] 配置键名和默认值与桌面端尽量一致
- [ ] 支持配置分层：默认值 < 文件值 < 环境变量 < 运行时覆盖
- [ ] 配置变更具备校验与回滚机制
- [ ] i18n 语言包沿用既有语言体系（中文/英文等）
- [ ] 文案 key 命名规范统一，避免页面硬编码

## 7. 接口清单（最小可运行）

- [ ] `GET /health`：服务健康检查
- [ ] `GET /runtime/state`：当前运行状态
- [ ] `POST /runtime/start`：启动运行态
- [ ] `POST /runtime/stop`：停止运行态
- [ ] `GET /tasks`：任务列表与摘要
- [ ] `POST /tasks/{id}/run`：触发指定任务
- [ ] `GET /config` / `PUT /config`：读取与更新配置

## 8. 日志与可观测性清单

- [ ] 日志等级与桌面端保持一致（debug/info/warn/error）
- [ ] 关键链路打点：启动、连接、任务开始、任务结束、异常
- [ ] 提供运行指标：任务成功率、平均耗时、失败分布
- [ ] 错误码体系统一，支持快速定位到模块
- [ ] 提供最近 N 条运行日志的查询能力

## 9. 安全与边界清单

- [ ] 接口输入参数校验与类型约束
- [ ] 敏感配置脱敏展示（token/key 等）
- [ ] 错误返回避免泄露内部路径与堆栈细节
- [ ] 任务执行权限边界明确（仅允许白名单动作）
- [ ] 静态资源与 API 路由隔离，防止路径穿越

## 10. 部署与运维清单

- [ ] Web 入口固定为 `python -m ok_web`
- [ ] 默认监听 `0.0.0.0:10086`，支持 `PORT/WEB_PORT` 覆盖
- [ ] 支持 `WEB_STATIC_DIR` 指定前端产物目录
- [ ] 反向代理层（Nginx/Caddy）处理 HTTPS 与缓存策略
- [ ] 启停命令、环境变量、健康检查写入部署文档

## 11. 兼容迁移清单

- [ ] 第一阶段：功能镜像（先能力对齐）
- [ ] 第二阶段：配置与任务定义兼容
- [ ] 第三阶段：日志、错误码、测试基线统一
- [ ] 迁移过程中保持桌面端能力不回退
- [ ] 关键配置提供兼容映射与废弃提示

## 12. 验收清单（Definition of Done）

- [ ] 启停流程行为与桌面端一致
- [ ] 核心任务执行语义一致（成功/失败判定一致）
- [ ] 配置项一致率达到目标值（项目自定义）
- [ ] 错误定位路径可闭环（日志 -> 模块 -> 原因）
- [ ] Web 版可稳定部署并通过健康检查与基本回归
